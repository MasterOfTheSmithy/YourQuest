# Offline training and integration boundary

The adapter interprets validated behavior and proposes bounded content. G15 owns evidence, G09 owns supported execution, G16 owns offers/content acceptance, G11/G14 own authorized NPC/social facts, and state/commit owners persist accepted canon. Numeric mechanics, eligibility, geography, knowledge, uniqueness and mutation remain deterministic. Generated names and prose never execute.

`schema.mjs` defines versioned offline record/output schemas; generated JSON Schema documents are compatible with direct JSONL workflows. `core.mjs` validates the exact schema-keyword subset used by those documents and fails on unknown keywords. Its deterministic gates check supplied IDs, eligibility flags, rarity ceilings, unique reservation, availability, missing/conflicting facts, accepted lineage, name collisions and obvious prohibited output. These are **fixture gates**, not replacement domain validators.

Version 0.2 additionally binds each proposal to a supplied destination, required canonical facts, objective IDs, permitted effect tags and any contact knowledge requirements. Every quest has an input-owned mock objective, and every future hook has supplied facts. Evidence sessions cannot exceed player history; an accepted parent's rarity cannot silently fall when its child evolves. All name candidates are checked for explicitly prohibited effect implications. These checks strengthen structural grounding; human review must still judge factual prose and whether an identity merits its approved ceiling. Mock objective text is never executable authority.

The model input comes only from an explicit task projection. Labels, expected answers, family/split metadata and source-review flags do not enter the prompt. Interpretation omits destination/canon material it does not need. NPC reaction excludes facts outside supplied NPC knowledge. Lore enrichment receives supplied facts and accepted content rather than the player's complete trace. Proposal/chain tasks receive compact evidence and available destinations. The current fixtures are intentionally small; token limits require the actual deployed tokenizer, template and output reservation before runtime use. Never truncate required facts to fit.

The eight main task tags and a separate NPC_NAME_GENERATION task route through one eventual model configuration. Adaptive names use IDENTITY_GENERATION with a category, supplied culture/context and a compact externally useful semantic kernel. Important-name seeds include candidate families and three final candidates. These are reviewable artifacts, not hidden chain-of-thought or fabricated numeric scores. NPC naming has a dedicated projection and given/family/clan/honorific/pronunciation parts; supplied species/people/region/role/age/pronoun and cultural context are nullable when not applicable, never inferred as canon. An immutable accepted NPC cannot be renamed through this task.

Names are normalized with Unicode preservation. Exact/normalized collisions are rejection gates; token and English Soundex similarities are advisory. Semantic collisions, pronunciation, memorability and motif saturation require representative review. Soundex does not certify names across cultures. No embedding model or vector database is introduced. Intentional accepted lineages have narrow collision exceptions; names unrelated to the supplied parent cannot borrow that exemption.

The seed catalog uses only `fixture:` IDs. `fixture:template:melee` and `projectile` illustrate supplied destinations; the presentation, quest and conversation templates are mock boundary fixtures. **There is no binding from these fixtures to actual G09 runtime executors.** Do not export these as production training targets until a reviewed runtime mapping replaces mock destinations and verifies their complete capability contract. No new mechanics are implemented by this package.

`family-seal.json` predates synthetic expansion. Tree variants remain in one family, as do identical-mechanic/different-history naming pairs. Synthetic prompt preparation uses train families only. Filters quarantine invalid candidates; exact duplicate inputs are not training material, while legitimate counterfactuals are retained together. Near duplicates and semantic overlap require review. Hidden-family placeholders do not constitute a hidden test corpus: an independent owner must author, hash and seal actual inputs before the authorized final comparison.

The revised train split has 42 original candidates across all nine task tags, including rare/unique proposals and accepted ancestry. Its mix is 16 none, 10 incubate, 10 personalized, five rare and one unique. Versioned initial-band checks guard this preparation snapshot; the bands remain adjustable through reviewed evaluation evidence. The planned 200-record mix is 70 none, 50 incubate, 48 personalized, 24 rare, seven unique and one legendary-chain. The exceptional legendary seed is review-only and cannot enter training. Teacher output is never automatically approved. No private traces are ingested.

Training remains a NOT_RUN proposal. Match source-weight/tokenizer revisions first; pin and test an environment; run a zero-adapter PEFT-to-GGUF export/load canary; then a bounded text-only BF16 pilot. Enumerate actual hybrid-model modules rather than blindly targeting all linear layers. Freeze base/vision/embeddings/lm_head. Choose rank/context/learning rate using validation and measured memory. Preserve complete commands, hashes, versions, seed, losses, checkpoints, elapsed time and peaks. Quantization training and export compatibility must be demonstrated on the actual model/backend.

If useful adaptation is established, use the existing G03 request path and one stable startup configuration. Preserve profile/world/epoch/owner/dependency binding, cancellation, timeout, stale rejection and exactly-one terminal outcome. A typed adapter option must preserve the existing live-presentation residency safeguard; do not append an unreviewed extra argument. No adapter swapping, second scheduler or permanent second model is proposed. A merged quantized artifact is conditional on measured compatibility and comparable quality/resource results.

Accepted identity/name/lineage/motif/evidence/canonical references and model/adapter/generation provenance must persist with the existing accepted record. Use a compatible owning-record or versioned payload extension only after inspecting actual contracts and migration requirements. Never regenerate accepted names on reload. No persistent extension or migration is implemented here. Final model-off replay compares accepted IDs, strings, lineage and effects, not merely similar-looking prose.

Integration blockers remain G03 relevant dependencies/token accounting, G09 validated executors, G15 durable evidence/candidate authority and G16 typed atomic offer/effect persistence. This offline work does not redesign or silently implement those goals, modify G08, or turn a queued specification into an acceptance claim.
