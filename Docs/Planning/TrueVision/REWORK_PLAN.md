## A. Executive assessment

**Decision:** retain Unity/C#, the authoritative player, generated record models, local-model transport, reviewed assets, and V2 spatial planning. Rework the connections between them around typed action attempts, explicit executable capabilities, and one revisioned commitment boundary. Prove a small populated area and two behavior-driven discoveries before increasing world size or supported genres.

**VERIFIED:** the production bootstrap starts player/world state managers, action recording, world and progression thinking, behavior rollup, origin/world generation, NPC dialogue, a quest evaluator, and a compiled-world materializer [E1]. This is substantial reusable work. The current failures do not justify replacing the engine, importing another procedural framework, or restarting the whole project.

The largest gaps are specific:

1. An attack on a tree cannot currently provide the proposed discovery system with a stable tree identity and a failed woodcutting attempt. Combat filters targets to enemies before recording a generic combat event [E2].
2. Skill offer acceptance preserves identity/tier information but omits executable fields. The combat path exposes only a narrow subset of the variety suggested by generated descriptions [E4].
3. Several consumers share a mutable event list and can clear it after asynchronous work [E3]. There is no reliable shared evidence cursor in that path.
4. World acceptance checks ground/collider presence more strongly than actual accessibility. A route can be marked valid with structural blockers [E7].
5. Quest completion uses cumulative counters, while profile persistence copies player and world files sequentially. Neither boundary establishes the complete causal transaction required by the vision [E9, E10].

The smallest high-value foundation is therefore **stable identity + typed attempts + capability records + idempotent commit + traversable area acceptance**. More prompts, larger word pools, increased scatter counts, or a larger language model would leave these gaps intact.

**Risks:** semantic asset contracts can overstate runtime readiness; legacy migrations can overwrite accepted state; hidden discovery can become tedious repetition; local inference competes with rendering; a valid schema can still describe an impossible action. Zero frame spikes cannot be guaranteed by coroutines or static inspection. Set measured budgets and reject preparations that exceed them.

**Proof before expansion:** two discoveries must change executable behavior, preserve their evidence and later consequences through reload, and occur inside a world slice with independently checked traversal, population, and visual presentation. Pipeline success and enjoyable play are separate gates.

## C. Recommended architecture

**PROPOSED:** one Unity application, existing state managers, pure record/validation helpers, and one small commit coordinator. Do not introduce distributed services, event sourcing of every footstep, or an LLM-controlled gameplay loop.

```text
Player input + resolved target → synchronous attempt/result observation
  → bounded journal → aggregate → provisional interest hypotheses
  → candidate enumeration from supported capability/operation registry
  → lore/context/access evaluation → director arbitration
  → deterministic selection; optional asynchronous LLM configuration/prose
  → schema/domain/reference/version validation → atomic commit
  → capability available → player reveal/use → persistent consequences
  → subsequent observations
```

Ownership: `ActionRecorder` captures completed authoritative action results; `EventAccumulator` becomes a bounded sequence journal. `PlayerBehaviorRollup` maintains typed aggregates. `ProgressionMath`/`ProgressionThinkCycle` host qualification and scheduling through adapters. `YQInvestorDirector` becomes the sole response arbiter; world/progression thinkers propose rather than independently award or mutate. `PlayerState` owns player capability/quest/item state; `WorldState` owns entity/fact/relationship/world-operation state. Existing spatial compiler prepares geometry outside the commit critical section. `LLMClient` transports proposals only. A proposed `YQChangeCommitter` serializes accepted changes across both managers and emits post-commit notifications.

Synchronous: input, hit checks, authoritative mechanical result, small observation append, final prepared state swap. Asynchronous/cooperative: asset preparation, aggregation batches, context/JSON processing, model request, snapshot persistence. Unity objects are accessed only on the main thread; worker inputs are immutable plain records. Every job carries world ID, session epoch, request ID, relevant revisions and cancellation ownership. Failure never leaves input waiting for an LLM response.

LLM decisions: contextual naming, prose, bounded role/personality detail, supported composition suggestions, causal opportunity framing. Deterministic decisions: actual target, evidence accounting, permission/cost/loot, qualification caps, executable support, reference/knowledge checks, selection budgets, terrain/collision, commit, reward and save. Model-reported confidence is not authorization.

## D. Core data contracts

All following types and filenames are **PROPOSED**. Implement serializable C# plain records compatible with existing Newtonsoft JSON, not Unity object references or polymorphic arbitrary payloads. Keep existing stable string IDs behind validated wrappers/adapters. Full field sketch: [CONTRACTS.md](C:/Users/Garri/YourQuest/Docs/Planning/TrueVision/CONTRACTS.md).

Identity invariants: `WorldId` scopes every persistent entity; streaming instance IDs are not entity identity. Procedural entity IDs derive from accepted area ID + stable slot ID + spawn incarnation, with collision checks. Persist random identities on first commit. Definitions have version/hash, instances have revision/state. Never use display names to authorize, target, merge or reward. Facts carry authoritative provenance; beliefs refer to fact/claim IDs plus knowledge source and certainty; rumors remain claims. Interest confidence never becomes a world fact about player intent.

Versions: envelope schema, content schema, primitive runtime version, generator version, validator version, asset-contract hash and world snapshot generation are distinct. Store accepted normalized definition and hash: the seed alone cannot reproduce stochastic model output. Pin deterministic algorithms and stable iteration/tie breaking. Store request/context hashes and limited diagnostic raw output, not an unrestricted transcript in every save record.

Atomicity: `proposalId` deduplicates input, `changeSetId` identifies accepted operations, `(changeSetId, operationIndex)` identifies effects/rewards, and unique capability/instance keys reject semantic duplicates from different proposal IDs. All preconditions pass before mutation. Recheck revisions immediately before prepared state swap. Notify UI only after successful commit; durable discoveries require snapshot/receipt persistence before announcing permanence. Ordinary combat remains synchronous and saves by checkpoint; crash policy restores the last coherent checkpoint.

## E. Generalized discovery lifecycle

**PROPOSED lifecycle:** Captured → Aggregated → Hypothesized → Qualified → Proposed → Validated → Granted → Revealed → Used → Remembered. Rejected/deferred/declined/expired states are explicit. Grant and reveal are separate: no notification may claim availability before capability commitment; on reload, undelivered reveals can retry once using a presentation receipt.

Record attempts even when the target is unsupported or capability is locked: attack tree, probe ground with shovel, attempt repair, interact with unreachable object. The authoritative resolver records `CapabilityLocked`, `UnsupportedOperation`, `InvalidTool`, `OutOfRange`, `Blocked`, `NoTarget`, `FailedExecution`, or `Succeeded`. A classifier never pretends a null target means tree interest. Use semantic target tags, valid contact/reach, equipped tool definition, location, context and outcomes. Essential movement and UI failures do not become reward farming.

An authored vocabulary provides target categories (vegetation, mineral, container, actor, surface, device), affordances (damage, gather, inspect, repair, trade, unlock), tool functions, context conditions, and executable effects. Generic rules match these axes. This supports many resources, social opportunities and context-sensitive abilities without an authored profession for every combination. A genuinely new physical operation still needs an implemented primitive.

**Initial tuning hypotheses, not measured design:** aggregate per behavior family in 20-minute active-play windows. Count at most one evidence unit per target/tool/result class per 10 seconds; each encounter contributes at most4 units. Treat a return after90 seconds away as a distinct visit. Retain distinct-target/location/tool counts separately, with bounded sets or compact sketches; durable milestone evidence keeps exact IDs.

Let `R=min(effectiveUnits/12,1)`, `V=min(distinctTargets/3,1)`, `T=min(toolFunctionsTried/2,1)`, `D=min(distinctVisits/3,1)`, `C=contextFit` in [0,1], and `G=redundancyFraction` in [0,1]. Initial score `S=clamp01(.25R+.20V+.15T+.25D+.15C-.25G)`. Qualification requires S≥.65, at least two meaningful visits, and a registry-supported response. Confidence is a tunable inference score, not measured probability. Ordinary attacks on enemies do not imply harvesting; contextual evidence must match the candidate.

Examples: one accidental tree hit with suitable context gives roughly .29, fails visits and score. Repeated exploration of three trees with two tool functions across three visits and low redundancy can exceed .9. A stationary macro on one tree has capped R, one target/visit, high G; more repetitions cannot bypass the qualification gate. Dedicated same-tree interest is still possible across meaningful returns: provide a costly practice/inspection opportunity that supplies alternate evidence; do not require arbitrary travel or hundreds of hits. Pure risk-free repetition may receive acknowledgment but no unlimited resources, XP or escalating rewards.

Shovel case: two ground types, appropriate inspection/probing, revisits near a known ruin, and examination of environmental clues qualify excavation opportunity. Qualification does not create treasure under the player's feet. It can reveal an existing permitted cache or commit a prospecting invitation linked to an already plausible site. Woodcutting and excavation differ in primitive/tool/target definitions but use the same evidence, lifecycle and commit logic.

Evidence policy: raw detail expires/compacts; hypotheses decay with active play (initial half-life3 active hours), while completed accomplishments and evidence cited by permanent grants remain. Lack of new behavior lowers interest priority, never silently removes a learned capability. Maintain concurrent hypotheses without exclusive classes. Declines suppress that response family for an initial hour or until materially new evidence; major transformations require consent. Accessibility input rates, remaps and assistive repetition must not be treated as proof of cheating. Deterministic contribution caps protect balance without mind-reading or hardware fingerprinting.

Feedback/pacing hypotheses: subtle contact response immediately; acknowledgment after several credible attempts (at most once/family/2min); optional opportunity at most once/5min; capability reveal initially at most once/15min with a global budget; major ability/title at least30min apart; rare transformation requires a durable accomplishment chain and explicit acceptance. These are maximum rates, not timers that force a reward. Feedback can show changed tool response, a local comment, contextual hint or brief generated reflection. After grant, accessible UI explains actual controls, costs, targets and limits from normalized mechanics; discoverability must not obscure usability.

## F. Director and world autonomy

**PROPOSED:** one transparent candidate policy. Hard gates first: supported operation, evidence qualification, available content, valid references/lore/knowledge, reachable target, capability prerequisites, budget, no equivalent outstanding opportunity. Then score eligible candidates:

`priority = .25*interest + .20*causalRelevance + .15*novelty + .15*worldNeed + .10*readiness + .10*variety + .05*contentReadiness - .20*recentRepetition - .15*commitmentLoad - .10*generationCost - .15*uncertainty`.

All values normalized, weights provisional. Deterministic ties use world seed + decision sequence + candidate ID. Store scored reasons in developer diagnostics. Keep the top candidate or defer if none meets a minimum .35; no forced daily award. Limit initially to three unresolved opportunities, one outstanding capability offer, one model composition request. Dialogue gets transport priority but cannot consume unlimited background work.

Reserve initially 40% of opportunity budget for independent world needs, 40% interest-related and20% novelty, with bounded carry-forward rather than starvation. Existing merchants have stock, needs and schedules whether the player likes commerce or not. Discovering information about a cave changes player knowledge; spawning a justified camp is a separately validated world operation with land/occupancy/time permissions. Never rewrite an explored cave, NPC past, inventory or relationship to make a proposal fit. A discovered opportunity can fail, cost resources, cause hostility, or remain too dangerous.

Proposal validation sequence: envelope/version/size → registry support → typed field/range/composition → entity/reference/knowledge → lore constraints → feasibility/access and economic bounds → dedup/pacing → revision preconditions → prepared changes. In-flight change: capture world/session + read-set entity revisions and artifact hashes. On response, discard wrong world/session; reevaluate changed read-set.
